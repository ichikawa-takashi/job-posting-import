# 求人票サイト

```
求人票/
├── public/          ← このフォルダの中身をサーバーにアップします
│   ├── .htaccess
│   ├── job.php          求人票ページ
│   ├── render.php       描画処理
│   ├── theme.css        デザイン
│   ├── data/
│   │   ├── .htaccess    JSONへの直接アクセスを禁止
│   │   └── jobs/        1求人＝1ファイル（<id>.json）
│   └── admin/           管理画面（ログイン必須）
├── json/            Cowork が作成した取り込み用JSON（手元保管）
├── pdf/             元の求人票PDF（サーバーには上げません）
└── _archive/        旧バージョン
```

## 求人票が独立している仕組み

`job.php?id=xxx` は `data/jobs/xxx.json` **1ファイルだけ**を読み込みます。
他社のデータはHTMLにもJSにも一切含まれません。
さらに `data/.htaccess` でJSONへの直接アクセスを禁止しているため、
URLを叩いてデータを覗くこともできません。

求職者に渡すURLはこの形です。

```
https://（ドメイン）/job/mynavi-works/
```

一覧ページは公開していません。管理画面の中だけにあります。

## サーバーへのアップ手順（初回）

1. `public/` の**中身**をドキュメントルート（`public_html` など）にアップロード
   - 隠しファイルの `.htaccess` も忘れずに（FTPソフトの「隠しファイルを表示」をON）
2. `data/jobs/` フォルダのパーミッションを **707 または 777** に設定
   （PHPから書き込めないと管理画面で保存できません）
3. ブラウザで `https://（ドメイン）/admin/` を開く
4. ログイン後、すぐにパスワードを変更してください

```
初期ID       : admin
初期パスワード : （伏せています）
```

### 設置場所

ドキュメントルート直下でも、`/recruit-file/` のようなサブディレクトリでも動きます。
設置場所は自動で判定します。

```
直下に置いた場合      → https://example.com/admin/
                        https://example.com/job/mynavi-works/

recruit-file に置いた → https://example.com/recruit-file/admin/
                        https://example.com/recruit-file/job/mynavi-works/
```

自動判定がうまくいかないときだけ、`public/_base.php` の1行目付近を書き換えます。

```php
const BASE_URL_OVERRIDE = '/recruit-file';
```

### 動作要件

- PHP 7.4 以上（8.x 推奨）
- Apache ＋ `.htaccess` 有効（`mod_rewrite`、`AllowOverride All`）

## うまく表示されないとき

まず **`check.php`** を開いてください。設置状態を診断します。

```
https://（ドメイン）/（設置場所）/check.php
```

ファイルの有無・書き込み権限・判定したベースURL・mod_rewriteの状態が一覧で出ます。
**原因が分かったら check.php はサーバーから削除してください。**

| 症状 | 原因と対処 |
|---|---|
| `/admin` が404 | `public` フォルダごと上げていませんか。正しいのは `public` の**中身**です。`/…/public/admin/` になっていないか確認してください |
| `/admin` が404（続き） | `admin` フォルダ自体がアップされていない可能性。FTPで再送してください |
| `/admin/` は開くがデザインが崩れる | `theme.css` がアップされていません |
| `/job/xxx/` だけ404 | mod_rewrite か AllowOverride が無効。`/job.php?id=xxx` は開けるはずなので、まずそちらで確認を |
| 保存すると「書き込めません」 | `data/jobs/` のパーミッションを 707 か 777 に |
| 403 が出る | `.htaccess` がサーバーの設定と競合。中身を一時的に空にして切り分けてください |

Nginx の場合は `.htaccess` が読まれないため、`/job/xxx/` は使えません。
`/job.php?id=xxx` を使うか、サーバー設定に次を追加してください。

```nginx
location /recruit-file/job/ {
    rewrite ^/recruit-file/job/([A-Za-z0-9_-]+)/?$ /recruit-file/job.php?id=$1 last;
}
location /recruit-file/data/ { deny all; }
```

## 更新の流れ

求人票を追加するときは、**毎回まっさらな新しいチャットで始めてください。**
前の会話を続ける必要はありません。手順とルールはすべて
`job-posting-import` スキルと、このフォルダの中に入っています。

```
① PDF を pdf/ フォルダに入れる（ファイル名は変えなくてOK）
        ↓
② 新しいチャットで「求人票追加しました」と言う
   （複数社まとめてでも大丈夫。/job-posting-import と打ってもOK）
        ↓
③ AI が PDF を読み、Web で調べて json/ に JSON を書き出す
   → tools/check-json.py で自動点検（給与の計算・禁止語・項目の抜け）
        ↓
④ push.command をダブルクリック → 内容を確認 → y
        ↓
⑤ 限定公開で取り込まれるので、管理画面で確認
        ↓
⑥ 公開状態を「公開中」にする → 一覧にも載る
```

チャットが長くなってきたら、区切りのいいところで新しいチャットに移ってください。
**この仕組みは会話の履歴に依存していません。**

### JSONの自己点検

```bash
python3 tools/check-json.py             # json/ の全件
python3 tools/check-json.py json/x.json # 1件だけ
```

給与が20〜30万円に収まっているか、想定年収が月給×12＋賞与2ヶ月と合っているか、
禁止語が混じっていないか、項目が抜けていないかを機械的に確認します。
「すべて問題ありません」と出れば送信してOKです。

### push.command（ワンクリックで送信）

フォルダ直下の `push.command` をダブルクリックし、確認に `y` を入力するだけで、
`json/` の中のJSONが本番サーバーへ送られます。
送信できたJSONは `json/_sent/` へ自動で移動するので、二重送信が起きません。

#### 公開状態の扱い

| 対象 | 挙動 |
|---|---|
| **新規**の求人 | 限定公開で入る（管理画面で確認してから「公開中」にする） |
| **既存**の求人 | 内容だけ差し替わり、**公開状態はそのまま維持される** |

つまり、**すでに公開中の求人が取り込みで限定公開に戻ることはありません。**
`json/` に入っているJSONだけが送信対象なので、他社の求人には一切触れません。

#### 管理画面で入れた内容はどうなるか

同じIDを送り直したときの挙動です。

| 項目 | 挙動 |
|---|---|
| 公開状態（公開中／限定公開／非公開） | **維持される** |
| 成約フィー | **維持される**（管理画面でのみ入力する項目のため） |
| 求人票の本文（原稿・給与・研修など） | **送ったJSONの内容で置き換わる** |

管理画面で文章を直したあとに同じIDを送り直すと、その修正は元に戻ります。
`push.command` は送信前にサーバーを調べ、`更新（公開中）` のように表示して
`y` の前に知らせます。置き換えたくない求人があれば、そこで中止して
`json/` から外してください。

守りたい項目を増やすときは `public/admin/config.php` に1行足します。

```php
const PRESERVE_ON_IMPORT = [
    'fee',   // 成約フィー
];
```

設定は `push.command` の冒頭にあります。

```bash
PUBLISH="false"   # true にすると、新規の求人を最初から公開状態で入れる
FORCE="false"     # true にすると、既存求人の公開状態も PUBLISH で上書きする（通常は false）
```

`FORCE="true"` は既存の公開中求人を限定公開に戻してしまうため、
一括で戻したいとき以外は触らないでください。

初回のみ、macOS の警告が出ることがあります。その場合は
`push.command` を右クリック →「開く」→「開く」で許可してください。

サーバーを移した・トークンを変えたときは、`push.command` の冒頭2行を書き換えます。

```bash
API_URL="https://ichi-web-home.com/recruit-file/public/api/import.php"
API_TOKEN="（admin/config.php の API_TOKEN と同じ値）"
```

## API

`public/api/import.php`

### 疎通確認（トークン不要）

```
GET api/import.php?ping=1
→ {"ok":true,"service":"job-import","ready":true}
```

`ready:false` のときは、トークンが未設定か `data/jobs/` に書き込めていません。

### 投入

```
POST api/import.php?overwrite=true
Authorization: Bearer <API_TOKEN>
Content-Type: application/json

{ "jobs": [ { "id": "example", "company": "株式会社◯◯", ... } ] }
```

本文は `{単体}` `[配列]` `{"jobs":[...]}` のいずれでも受け付けます。

| 項目 | 内容 |
|---|---|
| 認証 | `Authorization: Bearer` または `X-Api-Token` ヘッダー |
| トークン | `admin/config.php` の `API_TOKEN` |
| 新規の状態 | 既定は**限定公開**。`publish=true` で公開状態に（`API_ALLOW_PUBLISH = false` の間は無視され必ず限定公開） |
| 既存の状態 | **サーバー側の現在の状態を維持**。`force=true` を付けたときだけ `publish` で上書き |
| 上書き | `overwrite=true` を付けたときだけ既存IDの内容を更新 |
| 上限 | 本文2MB／一度に50件 |
| ログ | `data/api.log`（Web経由では見えません） |

応答例：

```json
{ "ok": true, "added": ["example"], "updated": [], "skipped": [],
  "message": "限定公開として取り込みました。..." }
```

**トークンが漏れた場合**は `admin/config.php` の `API_TOKEN` を別の文字列に
書き換えれば、その時点で古いトークンは無効になります。
APIを止めたいときは空文字（`''`）にしてください。

取り込みは**既定で限定公開**です。確認してから「公開中」に切り替える運用になります。
同じIDが既にある場合はスキップされます（上書きしたいときはチェックを入れてください）。

### 管理画面でできること

- 求人の新規作成・編集・複製・削除
- 公開状態の切り替え（公開中／限定公開／非公開）
  ・限定公開 … URLを知っている人は開ける。一覧には管理者にしか出ない
  ・非公開 … URLを開いても404。管理者だけ確認できる
- JSON読み込み（1件でも複数件でも、ドラッグでも貼り付けでも可）
- パスワード変更（発行された1行を `admin/config.php` に貼り替え）

## 表示用の言い換え（施工管理 → 不動産事務）

`public/terms.php` に言い換え表を持っています。

| どこ | 表記 |
|---|---|
| データ（`data/jobs/*.json`） | **施工管理**（そのまま） |
| 管理画面（`admin/`） | **施工管理**（そのまま） |
| 一覧ページ（`list.php`）のカテゴリ | **施工管理**（そのまま） |
| **求人票（`job.php`）** | **不動産事務** に置き換わる |

求職者が見る求人票でだけ言い換わります。データは書き換えていないので、
やめたくなったら `terms.php` の表を空にするだけで元に戻ります。

`job.php` が JSON を読んだ直後に `apply_display_terms()` を通しています。
`category` `id` `status` `fee` は対象外です。

### 言い換え表を直すとき

`public/terms.php` を編集します。**順番が重要です。** 上から順に置換するため、
長い言い方・文脈のあるものを先に置きます。

```php
'施工管理技士は国家資格です' => '建築系の国家資格です',   // 文脈があるものを先に
'施工管理技士'               => '建築系の国家資格',
'施工管理'                   => '不動産事務',              // 一般ルールは最後
```

資格名は「建築系の国家資格」に、人を指す場合は「建築技術者」に寄せています。
そのまま置換すると日本語が壊れる箇所（「事務ではなく、施工管理として」など）は、
文脈つきの例外として個別に登録しています。

### 新しくJSONを作るとき

**Cowork 側は原本どおり「施工管理」と書きます。** 先に「不動産事務」と書いてしまうと
二重に言い換えられて崩れます。`tools/check-json.py` が検査します。

## 項目について

全求人で同じ項目セットを使っています。**空欄にした項目はページに表示されません。**
「1日のスケジュール」を1件も入れなければ、そのセクションごと消えます。

| セクション | 内容 |
|---|---|
| 基本情報 | ID・職種カテゴリ・会社名・職種名・見出し・応募ボタンのリンク先 |
| トップ | タグ／キャッチコピー／リード文／サマリー（月給・年収など） |
| 数字で見るポイント | 「120名以上」のような訴求数字 |
| サービス・働き方の紹介 | 制度名の説明、特長、ステップ表示 |
| 仕事内容 | リード／箇条書き／カード／補足ボックス |
| 実績・プロジェクト | 濃色ボックスで見せる実績 |
| 1日のスケジュール | 時刻＋見出し＋説明のタイムライン |
| 魅力・やりがい | カード形式 |
| 研修・育成 | カード＋補足 |
| 求める人物像 | 必要条件（左）／歓迎・内定可能性（右） |
| 募集要項 | 項目名＋内容＋注記の表 |
| 選考フロー | ステップ（最後が自動で強調されます） |
| 理念・ビジョン | 大きく見せる文＋本文 |
| 会社情報 | 紹介文＋会社データ表 |
| 成約フィー | **社内用。一覧ページにだけ出ます**（求人票には一切出ません） |

項目を増やしたいときは `admin/admin.js` の `SCHEMA` と `render.php` に1つずつ足します。

## 別の人に使ってもらう

### 渡すもの

| 渡すもの | 中身 |
|---|---|
| `job-posting-import.skill` | 求人票を作るルール一式。開いて「スキルを保存」を押すだけ |
| `求人票-配布用.zip` | `push.command`／`tools/`／`json/_sent/`（過去の実例）／空の `pdf/` `json/` |
| 一覧ページの ID とパスワード | `（伏せています）…/public/list.php` で登録内容を確認するため |

`求人票-配布用/push.command` には**その人専用のトークン**が入っています。
`pdf/` は空にしてあるので、元PDFは渡りません。

### トークンの管理

`public/admin/config.php` で人ごとに1本ずつ持たせます。

```php
const API_TOKENS = [
    'ichikawa' => '…',
    'member2'  => '…',
];
```

- **追加**するとき … 1行足す
- **外す**とき … その1行を消す。他の人のトークンは影響を受けません
- **全部止める**とき … 配列を空 `[]` に

誰がいつ送信したかは `data/api.log` に残ります。

```
[2026-08-04 10:12:33] 203.0.113.8 by=member2 IMPORT added=1 updated=0 skipped=0 publish=no force=no
[2026-08-04 10:31:02] 198.51.100.4 by=- AUTH FAILED
```

新しいトークンの発行はどちらでも。

```bash
php -r "echo bin2hex(random_bytes(24));"
python3 -c "import secrets;print(secrets.token_urlsafe(32))"
```

### 人が増えても壊れないところ

サーバーは1つなので、**誰が追加しても同じ一覧・同じデザインに反映されます。**
求人IDが重複した場合は、`overwrite=true` により後から送ったほうで内容が上書きされます
（公開状態は維持されます）。同じ会社を2人で同時に触らないよう、担当を分けてください。

## 一覧ページ（社内用・ログイン必須）

```
https://（ドメイン）/（設置場所）/list.php
```

**管理画面と同じIDとパスワードでログインします。**
セッションを共有しているので、管理画面にログイン済みならそのまま開けます。
管理画面のヘッダーの「一覧ページ」からも移動できます。

未ログインのアクセスでは、社名・URL・成約フィーがHTMLに一切出力されません
（認証を通る前にデータを読まない構造にしています）。
8時間で自動ログアウト、5回失敗で60秒ロックも管理画面と同じです。

### リンクをまとめてコピーする

各行の左のチェックボックスを選ぶと、画面下から「◯件のリンクをコピー」が出ます。
押すと社名とURLがクリップボードに入ります。

```
パーソルエクセルHRパートナーズ株式会社
https://…/job/persol-excel-hr-partners/

マンパワーグループ株式会社
https://…/job/manpowergroup/
```

カテゴリ見出しの「このカテゴリをすべて選ぶ」で一括選択できます。
検索や絞り込みで隠れた行は、選択から自動で外れます。

### 成約フィー

管理画面の「成約フィー」で入力します。**一覧ページにだけ表示され、
求職者に渡す求人票（job.php）には一切出ません。**

**各行の右上にバッジで表示されます。**

| タイプ | 入力するもの | バッジ |
|---|---|---|
| 固定額 | 金額 `50万` | 紺色に `50万` |
| パーセント | 料率 `30%` | 紺色に `30%` |
| 期間限定フィーアップ | 期限 `8月末まで`／後 `100万`／通常 `80万` | **赤色**に3段で `8月末まで`／`100万`／`通常 80万` |

期間限定だけ赤にして、通常のフィーと見分けられるようにしています。
タイプを「設定しない」にすると、バッジ自体が出ません。
備考欄（任意）に入れた文言は、社名の下に小さく表示されます。

## セキュリティについて

| 対策 | 内容 |
|---|---|
| ログイン | PHPセッション。パスワードは `password_hash`（bcrypt）で保存 |
| 総当たり | 5回失敗で60秒ロック、8時間で自動ログアウト |
| CSRF | 保存・削除・公開はトークン照合 |
| JSON保護 | `data/.htaccess` で直接アクセスを拒否 |
| ID検証 | 英数字・ハイフンのみ許可（ディレクトリトラバーサル対策） |
| 検索避け | 求人票・管理画面・一覧ページすべて `noindex,nofollow` |
| 一覧ページ | ログイン必須。管理画面とセッションを共有。`no-store` でキャッシュも残しません |

さらに固めるなら、`/admin/` にサーバー側のBasic認証を重ねるか、
アクセス元IPを制限するのが確実です。
