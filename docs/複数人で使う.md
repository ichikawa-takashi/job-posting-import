# 複数人で求人票を追加する

キャリアアドバイザーが何人いても、**同じサーバー・同じ一覧ページ**に集まります。
誰が追加しても、全員に見えます。

---

## 引き継ぎに必要なもの（1人あたり）

| 渡すもの | 中身 | 渡し方 |
|---|---|---|
| `求人票作成ツール_利用手順.pdf` | 6ページの手順書 | メール・Slackなど |
| **送信トークン** | 40文字ほどの英数字。**人ごとに別のものを発行** | 個別に。全員共有にしない |
| 一覧ページのID・パスワード | 登録内容を確認するため | 個別に |

**管理者用のID（`hreed-admin`）は渡しません。** 公開ボタンを押すのは市川さんだけです。
| 実例JSON 2〜3件 | `json/_sent/` からコピー。文章のトーンの見本 | フォルダごと渡す |

**フォルダそのものは渡しません。** 相手は `/job-posting-setup` を実行すれば、
自分専用のフォルダが自動で作られます。

---

## 追加の手順（市川さん側）

### 1. トークンを発行する

ターミナルで実行します。

```bash
python3 -c "import secrets;print(secrets.token_urlsafe(32))"
```

### 2. サーバーに登録する

`public/admin/config.php` に1行足して、FTPでアップロードします。

```php
const API_TOKENS = [
    'ichikawa' => '…',
    'sato'     => '（いま発行した値）',   ← 追加
];
```

名前はログに残る識別子です。ローマ字の名字にしておくと、
`data/api.log` を見たときに誰が送ったか分かります。

```
[2026-08-14 10:12:33] 203.0.113.8 by=sato IMPORT added=1 updated=0 held=0
```

**外すときは、その1行を消すだけです。** 他の人には影響しません。

### 3. 本人に渡す

上の表の4つを渡します。

### 4. 本人の作業（10分ほど）

```
1. Claude デスクトップアプリをインストールしてログイン
2. 書類フォルダに「求人票」フォルダを作り、Cowork で選ぶ
3. /job-posting-setup と打つ
4. トークンを貼る
```

これで完了です。以後は市川さんとまったく同じ操作になります。

## 同時に使っても壊れない仕組み

サーバー側で1求人＝1ファイルに分かれているので、**別の求人を同時に登録しても
ぶつかりません。** 危ないのは「同じ会社を2人が別々に登録する」ケースだけです。

これは3段階で防いでいます。

### ① 作り始める前に、サーバーの現況を見る

`push.command` を実行するたびに、**全員ぶんの登録状況**が
`json/_server.json` に保存されます。

```json
{ "fetchedAt": "2026-08-14 10:00",
  "categories": ["事務", "施工管理"],
  "jobs": [ { "id": "yell", "company": "株式会社エール", "status": "published" } ] }
```

AI は求人票を作り始める前にこれを読み、同じ会社が既にあれば知らせます。
古ければサーバーへ取りに行って更新します。

### ② 送信前に、会社名の重複を警告する

別のIDでも同じ会社名があれば、`y` を押す前に止まります。

```
同じ会社が、別のIDで既に登録されています
  ！ 株式会社エール（yell-corp）
      既存：株式会社エール（yell）
  このまま送ると、一覧ページに同じ会社が2件並びます。
  ・既存を差し替えたい → 中止して、JSONのIDを既存のIDに変えてください
  ・別の求人として載せたい → そのまま y で進めて構いません
```

### ③ カテゴリの表記ゆれを防ぐ

職種カテゴリも**サーバーの実データを正**として照合します。
自分がまだ「営業」を登録していなくても、他の人が登録していれば
「営業職」と書いたときに警告が出ます。

```
新しい職種カテゴリ
  ★ 営業職   一覧ページに新しいセクションが増えます
     似た名前が既にあります：営業  表記ゆれではありませんか？
```

## それでも気をつけること

### 同じ求人を2人が同時に編集した場合

**後から保存したほうが残ります。** 履歴は取っていません。

管理画面で文章を直したあとに、別の人が同じIDで送信すると、その修正は消えます。
`push.command` は送信前に `更新（公開中）` と表示して知らせますが、
**誰が直したかまでは分かりません。**

大きく書き換えるときは、ひと声かけてから作業するのが安全です。

### 成約フィーと公開状態は消えません

管理画面でしか入力しない項目（成約フィー）と、公開状態（公開中／限定公開／非公開）は、
誰が送信し直しても維持されます。ここは仕組みで守っています。

### 一覧ページはログインが必要です

`list.php` は管理画面と同じID・パスワードでログインします。
成約フィーが表示されるページなので、**求職者には渡さないでください。**

---

## 運用の目安

人数が増えてきたら、次のどちらかを決めておくとスムーズです。

**担当を分ける**
職種カテゴリや媒体で分担する。ぶつかる確率がほぼゼロになります。

**追加する前に宣言する**
Slackなどに「〇〇社を追加します」と書いてから作業する。
`json/_server.json` があるので、AIも既存分は把握しますが、
**まだ誰も送信していない作業中のものは見えません。**

## 誰が何を追加したか調べる

サーバーの `public/data/api.log` に残ります。FTPでダウンロードして開いてください。

```
[2026-08-14 10:12:33] 203.0.113.8 by=sato     IMPORT added=1 updated=0 held=0
[2026-08-14 11:40:02] 198.51.100.4 by=ichikawa IMPORT added=0 updated=2 held=2
```

| 項目 | 意味 |
|---|---|
| `by=` | 誰が送ったか（`config.php` の `API_TOKENS` の名前） |
| `added` | 新しく追加された件数 |
| `updated` | 既存を更新した件数 |
| `held` | 成約フィーなどを引き継いだ件数 |

管理画面での編集はログに残りません。求人票の `updated` 欄で最終更新日時だけ分かります。
